# Coding standards

Read by the code reviewer, not the implementation agent. Anything that can be a deterministic check belongs in `scripts/check.sh`; this file covers the judgement calls a reviewer should apply.

## Source adapters

- A source module exports `NAME`, `collect(config, fixtures_root, now)`, and `check(config, fixtures_root)`.
- `collect` returns a `SourceResult`; one failed source never aborts the others.
- Fixture layout is `<fixtures>/<source>/<recorded-response>`. Use `base.read_or_fetch` so `--fixtures` never touches the network.
- Live GETs go through `base.get_text` / `base.get_bytes`, which retry connection errors, 5xx, and 429 up to three attempts with 1s/2s backoff; a read timeout or 4xx fails immediately. Fixtures bypass this layer, so `tests/test_source_http.py` tests the loop directly (a documented transport exception beside `test_push_transport.py`).
- A fixture must mirror the real response shape, including separators. bioRxiv authors, for example, are semicolon-separated `Last, First`.

## Candidate pool

- `attach_topic` owns group, tags, `relevance`, `abstract_missing`, and the preprint marker.
- `ranking.select_candidates` sets `score` (relevance plus the freshness bonus), orders the pool (score, date, id), reserves each non-empty group's best paper, and enforces each group's `max_items` plus `pool.max_items`. Config validation keeps `pool.max_items` at or above the topic count so every group's reservation fits. A short pool is never padded.
- Tag order: matched terms, then `预印本` when `is_preprint`, then `无摘要` when the abstract is empty.
- `is_preprint` is true only when every merged version is a preprint.
- Dedupe key priority: DOI > PMID > arXiv ID > normalized-title-plus-year.

## Output contracts

- The ticket's `## Contract` section (see `docs/agents/issue-tracker.md`) is the source of truth for payload keys and their placement.
- Existing payload keys keep their meaning, type, and shape; a new datum gets a new key. Changing an existing key's semantics requires the ticket to say so and a test that pins the new behavior and the keys that must not change.
- A ticket that names a destination block (for example G6) puts its data in that block's key (`g6_releases`), not in a sibling that only links back through a `group` field.
- A "no update means no block" requirement is implemented where the block is produced: omit it; do not leave empty lists for a later renderer to hide.

## GitHub discovery

- `academic_digest/github.py` exports `NAME`, `discover(config, fixtures_root, now)`, and `check(config, fixtures_root)`. It is deliberately outside the paper-source registry: a repository never enters `papers`.
- The token comes from `github.token_env` (default `GITHUB_TOKEN`). Config validation raises `github.token` before any request when it is empty, and the token never appears in output, logs, or the digest.
- `github.queries` maps a topic name to server-side queries; the default is the 22-query G1–G5 recipe. `github.g6_queries` feeds the G6 block; the default is the 12-query Claude Code/Codex/DSH list. Each query runs in both passes as `<query> created:>{since} stars:>={min_stars}` and `<query> pushed:>{since} stars:>={min_stars}`, with `sort=updated`, `order=desc`, and only the first page of 100 — `sort=updated` reshuffles while paging.
- Eligibility: new needs `created > since` and stars at or above `github.new.min_stars`; active needs `pushed > since` and stars at or above `github.active.min_stars`; forks and archived repositories are dropped. A repository's group comes from the query that returned it, so it is never dropped for matching no keyword.
- Scoring: `relevance` is 3 per group term in the full name, description, or topics, plus 1 per group term found only in the README. `score` adds `round(2 * log10(stars))` and push recency (today 2, yesterday 1). Ordering is score, stars, pushed-at, full name.
- READMEs come from `raw.githubusercontent.com`, which costs no API quota. Each section offers its best `max_items + README_SLACK` (3) candidates and the `github.readme_limit` budget (default 20) is shared round-robin, so a high-star active repository cannot starve the new or G6 sections of README evidence. A candidate outside the budget still competes for a slot, just without the README bonus. A missing README is empty, not a source failure. Search requests are serial with a two-second gap and carry a User-Agent and the token.
- Caps come from `github.new.max_items` (default 1), `github.active.max_items` (2), and `github.g6.max_items` (2). A repository selected as new never takes an active slot; a repository returned by a G6 query appears only in the G6 block, with G6 provenance even when a discovery query also returned it; a short section is never padded. `found` counts eligible repositories before the caps and before the cross-section exclusions. A failed run keeps `github.passes` (queries and partial item counts) so the attempt is auditable.
- Release tracking is configured by `github.user`, `github.official`, and `github.releases`. The starred list comes from `GET /users/{user}/starred` (first page, 100) and releases from `GET /repos/{owner}/{repo}/releases?per_page=30`; fixtures are `github/starred.json` and `github/releases/{owner}__{repo}.json`. A repository in both lists is read once and appears only as an official G6 release. Any release request failure fails the GitHub source, like a search failure. With neither `user` nor `official` configured, no release request runs and the `releases` block is omitted.
- A release is eligible when it is not a draft and its `published_at` local date falls inside `today - github.releases.days` through today, inclusive. A missing `published_at` is not replaced by `created_at`. Only one release per repository is kept, chosen by the full publication timestamp (a same-day tie is resolved by the later time). The starred section is ordered by local date desc, relevance desc, repository name, and capped at `github.releases.max_items` (default 2). Official releases are ordered by date desc and all enter the top-level `github.g6_releases` list, one per official repository and additional to the 1–2 ecosystem G6 repos; a repository without an update is absent, never padded. `releases` holds only the starred section (`since`, `days`, `limits`, `found`, `starred`). Each block is omitted when its list is empty, so a quiet day has no empty section.
- Release relevance reuses the topic terms: metadata hits weigh three and release-title-or-notes-only hits weigh one; an official release belongs to the G6 topic and is scored on its title and notes. `highlights` is the release body, or the release title when the body is empty, with CRLF normalized and trailing spaces removed. It is capped at 1000 characters including the ellipsis, cutting at a blank-line paragraph boundary when one falls in the second half of the budget, then at a line break, and only then at the character limit.
- `sources.github.count` still counts only the selected new / active / G6 repositories; release counts live in `releases.starred`, `releases.found.starred`, and the top-level `g6_releases` list.
- Fixtures: `github/search/{new,active}/{query-index}.json` follows query order, so query construction is observable in `github.passes.<pass>.queries`; READMEs are optional files at `github/readme/{owner}__{repo}.md`; the star list and release feeds are `github/starred.json` and `github/releases/{owner}__{repo}.json`, replayed by `doctor`.

## Full text

- Resolution order is fixed: Europe PMC OA XML, arXiv HTML then PDF, the bioRxiv/medRxiv/Research Square preprint PDF, then Unpaywall's best OA location. Each source records one `Attempt`; internal fallbacks (HTML→PDF, multiple OA candidates) collapse into that source's entry. The overall result is `no_oa` with a reason and exit code 0, never an exception.
- `fulltext.unpaywall.email` is optional: without it the Unpaywall attempt is skipped and the other sources still run. The email must not appear in the digest output; a live Unpaywall failure is sanitized because the request URL carries `email=...`.
- Extraction keeps methods/results/limitations only, deduplicated and capped at 4/3/4 paragraphs and 4000/3000/2000 characters, truncated at a sentence boundary in the second half of the budget when one exists, otherwise at a word boundary. `length` is the sum of the kept paragraphs; the two truncation fixtures pin the paragraph and character caps. When no explicit Limitations section exists, only Discussion/Conclusion prose may supply an author limitation; Methods/Results prose is not promoted by keyword.
- Every Europe PMC search hit must carry the requested DOI before its PMC id is used; a DOI-less neighbouring record is skipped.
- `--title` is optional and additive: `10.48550/arXiv.<id>` maps straight to an arXiv ID even without `--title`, and an exact normalized title is looked up in the arXiv API and then in Europe PMC's `TITLE:` search. Only a verbatim title match is accepted; a near-title record is ignored. The discovered preprint DOI / arXiv ID is tried before Unpaywall, title-lookup misses add no `Attempt`, and the output keys do not change.
- Fixture layout mirrors the source: `europepmc/doi-search.json` + `fulltext.xml`, `arxiv/fulltext.html|pdf`, `<preprint>/fulltext.pdf`, `unpaywall/location.json` + `fulltext.pdf|html`, and the optional `europepmc/title-search.json` / `arxiv/title-search.atom`. Binary fixtures go through `base.read_or_fetch_bytes`; `--fixtures` never touches the network.

## Digest contract

- `digest check` lives in `academic_digest/digest.py` and reads exactly three files: `candidates.json`, `selection.json`, `digest.md`. It must not load config, secrets, the state database, or the network. Exit 0 means valid, 1 means unreadable or invalid content, and argparse owns 2. It reports only the first violation, prefixed `[fail] selection:`, `[fail] digest:`, or `[fail] candidates:` for a corrupt pool.
- Selection quotas are checked before the digest: each id exists in `candidates.papers` with the same group, ids are unique, `must_read = min(3, n)`, `quick_scan = min(7, n - actual must_read)`, G2 ≤ 4, G6 ≤ 1 and only in `quick_scan`, and every candidate group except G2/G6 has at least one paper. A `must_read` shortfall is allowed only when no non-G6 candidate is left outside must_read to fill it (G6 papers may not be must-reads, and a paper already in quick_scan can be moved); a `quick_scan` shortfall only when the G2 four-paper cap or the one-G6-paper cap blocks every remaining candidate. Never pad.
- `must_read` entries require `fulltext` of `oa` or `abstract_only` and `limitations_source` containing `model`; `quick_scan` is `abstract_only` only. The digest must agree: an `abstract_only` must-read carries the literal `无 OA 全文，仅基于摘要` in `- 方法精读：`, an `oa` one must not.
- Paper titles are compared verbatim with the candidate `title` (never translated), once each, and the parsed title sets must equal the selection's two sections. The fixed Markdown labels (`- 标签：`, `- 摘要：`, `- 局限性：`, `- 方法精读：`, `[原文]`, and the one-line quick-scan fields) are parsed literally; unknown `##` sections are rejected.
- GitHub/G6 is driven only by `candidates.github`: `new`, `active`, and `releases.starred` populate `## GitHub`; `g6` and `g6_releases` populate `## AI 工具 / Agent Harness`. Each item must appear exactly once with its required fields, nothing extra, and an empty list omits its subsection or section. `g6` respects `github.limits.g6` (default 2); `g6_releases` is one per official repository and does not consume that cap. A repo's 最近更新 is its `pushed_at` local date (creation date only as a fallback); `language` may be empty; a release must show its 更新要点, not just a date and link.
- The footer must report every `candidates.sources` name with its status between `来源：` and `候选：`, `候选：N` equal to `candidate_count`, `入选：M` equal to the selection count, and an ISO-8601 `生成：` value. Secret-like tokens (`sctp`, `SendKey`, `GITHUB_TOKEN`, `Authorization`) in the footer are a failure. Content length, the 32KB split, and pending counts are out of scope here; `push` owns them.

## Push contract

- `push` lives in `academic_digest/push.py` and is the only code that talks to ServerChan. It first calls `digest.check_files` and must not send or write state when that fails. `--dry-run` builds the payload only: no SendKey read, no state database opened, no `runs`/`pushes`/`pending` write; `--out` is valid only with `--dry-run`.
- The payload is `标题 = 学术速递 · <candidates.date>`, with `（i/n）` suffixes only when split. The body is `digest.md` without its title line and with LF newlines. Lengths are counted in UTF-8 bytes; a title over `push.title_max` Unicode characters is exit 2, never truncated.
- A body over `push.split_bytes` is split only at top-level `## ` boundaries and never inside a section or paper. The first message carries the preface, the last carries the footer (and `未推送数：P` when older messages are still pending); every message is at most `push.max_bytes`. A body with no top-level boundary to split at (a lone section that opens the body) cannot be split without cutting into it, so it is exit 1. A section over `max_bytes`, or more than `push.max_messages` messages, is exit 1 with nothing sent.
- Success is HTTP 2xx plus an integer `code` of 0. Each message gets `1 + retries` attempts with `backoff_seconds × 2^(k-1)` between them; fixture runs never sleep. Only after the whole logical digest is delivered are `pushes` rows written. A failure stores the failed and unsent messages in `pending` (part/parts, title, desp, `items_json`, created_at, attempts, sanitized last_error), writes no `pushes`, and exits 1.
- On a live run, open the state database before sending. Drop `pending` groups whose oldest `created_at` is older than `pending_days` calendar days in the configured timezone (whole group keyed by `digest_date`, no `pushes`); retry the earliest remaining group once per part in `part` order; when the group is complete, write its `pushes` from `items_json`. Pending failures never block the current digest, but they go into `runs.error`; an empty skipped digest plus a failed pending retry is exit 1.
- An empty digest (no `selection.papers` and no GitHub/G6 items) sends one notice message when `send_empty` is true and is skipped otherwise; neither case writes `pending`, and a failed notice is a normal failure without pending. Every live push (sent, skipped, or failed) writes one `runs` row with `command='push'`, status `ok`/`skipped_empty`/`failed`, `sources_json='{}'`, and the candidate/selected/pushed/pending counts.
- The SendKey comes from `push.sendkey_env`; it is read only for a live, non-fixture send, and an empty value is exit 2. The key and any URL containing it must never reach stdout, stderr, the digest, or the state database. Every transport exposes `Sender.sanitize`; captured `SendError` text goes through it before it is stored in `pending`/`runs` or printed, and the live transport redacts the key with `push.redact`. Fixture responses replay `DIR/serverchan/send-<n>.json` in request order; a missing or non-JSON file is a transport failure. Tests may add `http_status` to a fixture to simulate a non-2xx response.

## Config

- Validate before any network request; raise `ConfigError(field, message)` with a dotted field.
- `github.official` entries must be `owner/repo` slugs, and a non-empty official list needs `github.g6_topic` to name a configured topic; without a G6 topic the default official list is empty. `github.releases.days` must be positive and `max_items` non-negative.
- An enabled source needs its `lookback` entry, except GitHub: it carries its own `github.new.days` / `github.active.days` windows. A missing `lookback` block means "no lookback-driven sources", so enabling one of them fails with `lookback.<source>` rather than a bare mapping error. arXiv additionally requires `arxiv.categories` and a four-day minimum.
- `push` is optional and every field has a default. `channel` is `serverchan` only; `split_bytes` ≤ `max_bytes`; `max_messages`, `title_max`, `timeout`, and `pending_days` are positive; `retries` and `backoff_seconds` are non-negative. Loading config never reads the SendKey environment variable.

## Tests

- Test at the CLI seam: subprocess `collect` / `fulltext` / `digest check` / `push` / `doctor`, asserting exit code, stderr, and output files. Two documented transport exceptions test what the fixture seam cannot reach: `tests/test_push_transport.py` (fixture runs never build a URL, read a SendKey, or sleep) covers endpoint selection, key redaction, the retry/sanitize wiring, and the transport-only `timeout` / `backoff_seconds` defaults; `tests/test_source_http.py` (fixture runs never reach `_request`) covers the source GET retry loop — connection errors, 5xx/429, the 1s/2s backoff, no retry for read timeouts or 4xx. Both fake HTTP and never sleep or touch the network.
- Tests stay offline and deterministic: pass `--fixtures` and a fixed `--now`; no sleeps or wall-clock dependencies. `fulltext` has no date logic, so its tests rely on `--fixtures` alone; `push` replays recorded ServerChan responses, so its tests pass `--fixtures` and never read a SendKey.
- Add a test whenever a documented ordering, marker, default, or switch changes. Every documented default (a config field that may be omitted) has a test that omits the field and asserts the documented value. Every "no update means no block" claim has a fixture with no updates that asserts the block is absent.

## Docs

- A doc claim about ordering, labels, or defaults must match a test or config fixture.
- Update `README.md`, `config.example.yaml`, and the ADR when a source or config contract changes.
